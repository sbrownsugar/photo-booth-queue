# ระบบคิว Photo Booth

เว็บรันคิวสำหรับบูธถ่ายรูปในงานอีเวนต์ — พนักงานกดเพิ่มคิว, มีจอประกาศ, และลูกค้าสแกน QR เช็กคิวจากมือถือได้แบบเรียลไทม์

## ไฟล์ในโฟลเดอร์นี้

| ไฟล์ | คืออะไร |
|---|---|
| `index.html` | หน้าพนักงาน + จอประกาศ (เปิดบนโน้ตบุ๊ก) |
| `status.html` | หน้าที่ลูกค้าเห็นเมื่อสแกน QR |
| `firebase-config.js` | ที่เดียวที่ต้องแก้ — ใส่ค่า Firebase ของคุณ |

---

## ขั้นที่ 1 — สร้าง Firebase (ทำครั้งเดียว ~5 นาที)

1. เข้า https://console.firebase.google.com แล้วล็อกอินด้วย Google
2. กด **Add project** → ตั้งชื่อ เช่น `photo-booth-queue` → กด Continue ไปเรื่อย ๆ
   (ตรง Google Analytics จะปิดก็ได้ ไม่ได้ใช้)
3. เมนูซ้าย **Databases & Storage** → **Realtime Database** → กด **Create Database**
   - ⚠️ ต้องเป็น *Realtime Database* เท่านั้น **ไม่ใช่ Cloud Firestore** (คนละตัวกัน ใช้แทนกันไม่ได้)
   - เลือกที่ตั้ง **Singapore (asia-southeast1)** — ใกล้ไทยที่สุด เร็วสุด
   - เลือก **Start in test mode** → Enable
4. เมนูซ้าย **Settings** → **General** (เมนูใหม่ไม่มีคำว่า "Project settings" แล้ว)
   → เลื่อนลงล่างสุดหัวข้อ **Your apps**
   → กดไอคอน **`</>`** → ตั้งชื่ออะไรก็ได้ → **Register app**
   (ไม่ต้องติ๊ก Firebase Hosting เพราะเราใช้ GitHub Pages)
5. จะเห็นโค้ดชุดหนึ่ง — ก๊อปเฉพาะค่า **`apiKey`** (ขึ้นต้นด้วย `AIzaSy...`)
   มาใส่ใน `firebase-config.js` แทนคำว่า `ใส่ค่าจริงตรงนี้`

> ค่าอื่น ๆ ในไฟล์ผมเติมไว้ให้แล้วจากชื่อโปรเจกต์ `queue-845ad`
> ถ้าตอนสร้างฐานข้อมูลเลือกที่ตั้งอื่นที่ไม่ใช่ Singapore ต้องแก้บรรทัด `databaseURL` เพิ่ม
> โดยก๊อปลิงก์ที่ขึ้นบนหน้า Realtime Database มาทับ

### ตั้งค่าความปลอดภัย (สำคัญ)

ไปที่ **Realtime Database → แท็บ Rules** แล้ววางทับของเดิม:

```json
{
  "rules": {
    "booths": {
      ".read": true,
      ".write": true
    }
  }
}
```

- `.read: true` = ใครสแกน QR ก็ดูคิวได้ (ต้องเป็นแบบนี้ ไม่งั้นลูกค้าดูไม่ได้)
- `.write: true` = ใครก็เขียนได้ **ถ้ารู้ลิงก์ฐานข้อมูลของคุณ**

ข้อมูลในนี้มีแค่เลขคิวกับชื่อเล่นลูกค้า ไม่มีเบอร์โทรหรือข้อมูลอ่อนไหว ความเสี่ยงจึงต่ำมาก
แต่ถ้าอยากล็อกให้แน่นขึ้นทีหลัง ค่อยมาเปิด Firebase Authentication แล้วเปลี่ยน `.write` เป็น `"auth != null"`

## ขั้นที่ 2 — เอาขึ้น GitHub Pages (~5 นาที)

1. เข้า https://github.com/new → ตั้งชื่อ repo ว่า `photo-booth-queue` → เลือก **Public** → Create
2. ในหน้า repo กด **Add file → Upload files**
3. **ลากไฟล์ทั้ง 3 ไฟล์** (`index.html`, `status.html`, `firebase-config.js`) จากโฟลเดอร์นี้ใส่ลงไป → Commit changes
4. ไปแท็บ **Settings → Pages** → หัวข้อ *Branch* เลือก **main** และ **/ (root)** → Save
5. รอ 1–2 นาที แล้วรีเฟรช จะเห็นลิงก์ประมาณ
   `https://ชื่อคุณ.github.io/photo-booth-queue/`

---

## ขั้นที่ 3 — ใช้งาน

1. เปิดลิงก์ GitHub Pages ข้างบนบนโน้ตบุ๊ก (**เปิดจากลิงก์ ไม่ใช่ดับเบิลคลิกไฟล์** — QR ถึงจะทำงาน)
2. ดูมุมขวาบน ถ้าขึ้นจุดเขียว **"ออนไลน์ — ลูกค้าเช็กคิวได้"** = พร้อมใช้
3. QR จะขึ้นเองในการ์ดขวามือ → กด **🖨️ พิมพ์ป้าย QR** เอาไปตั้งหน้าบูธ
4. กด **🖥️ เปิดจอประกาศ** → ลากหน้าต่างไปจอทีวี → กด `F11` เต็มจอ
5. รับคิว → เรียกคิว → กดเสร็จ

### ลูกค้าเห็นอะไร

สแกน QR → ใส่เลขคิวที่พนักงานบอก (เช่น `A005`) → หน้าจอจะบอกว่า **เหลืออีกกี่คิว / ประมาณกี่นาที**
และ **สั่นเตือน** เมื่อเหลืออีก 2 คิว ถ้าเปิดหน้าค้างไว้

## เน็ตหลุดจะเป็นยังไง?

ออกแบบมาให้ **หน้าร้านไม่พัง**:

| ส่วน | เน็ตหลุดแล้วเป็นยังไง |
|---|---|
| หน้าพนักงาน | ✅ ใช้ได้ปกติทุกอย่าง (ข้อมูลอยู่ในเครื่อง) |
| จอประกาศ | ✅ ใช้ได้ปกติ |
| QR ของลูกค้า | ❌ ค้างที่ข้อมูลล่าสุด และหน้าลูกค้าจะขึ้นเตือนว่า "ข้อมูลอาจไม่ใช่ล่าสุด" |

พอเน็ตกลับมา ระบบจะส่งข้อมูลล่าสุดขึ้นไปเองอัตโนมัติ ไม่ต้องกดอะไร

## จุดที่แก้ได้ง่าย ๆ ในโค้ด

เปิด `index.html` แล้วหาบรรทัดพวกนี้ (อยู่ต้น ๆ ของ `<script>`)

```js
const PREFIX = 'A';              // ตัวอักษรนำหน้าเลขคิว
const PACKAGES = [
  { id:'solo',  name:'เดี่ยว/คู่',  minutes:3 },   // แก้ชื่อ/เวลาให้ตรงกับร้านคุณได้เลย
  { id:'group', name:'กลุ่ม',      minutes:5 },
  { id:'big',   name:'กลุ่มใหญ่',  minutes:8 },
];
```
